# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 解析 ODS 台账，按逻辑单元格坐标采得记录；请求参数非法返回400，来源内容无法解释形成 rejected 收件而非抛异常。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 每个有语义内容的逻辑单元格一条，sheet/row/column 标识其坐标（坐标从1起），ref 为列字母+行号，id 为 `sheet!ref` 的稳定身份，不依赖数组下标，也不为重复空白造记录。记录字段：valueType（string/float/boolean/date/time）、value（缓存值，缺失为 null）、text（原文文本，保留重复空格与换行）、formula（公式表达式，无则缺省）、cache（公式缓存状态 cached/missing，非公式格缺省）、explicitEmpty（仅在空值格仍携带公式等语义时出现）。

合并单元格只在原点产记录；被覆盖位置不复制值，coverage.sheets[].merged 登记矩形、coveredCells 计数覆盖格。显式空值不产记录，仅当落在请求 region 内时计入 explicitEmptyCells；未给 region 时不统计空白尾部，避免凭格式化范围制造货位。issues 每条带 code 与可定位的 sheet/row/column，无法可靠解释的材料在此说明而不是静默丢弃。state 取值：无缺口 complete、仍有可采记录但存在问题 partial、无任何可解释记录 rejected；coverage.truncated 表示达到记录上限后的截断。
